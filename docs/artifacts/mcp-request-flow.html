Luồng request khi user gửi một yêu cầu ghi

MCP chỉ là lớp vận chuyển context và hành động. Control plane nằm ngoài giao thức và là nơi policy, approval, idempotency và trace thực sự được thực thi. Sơ đồ dưới vẽ trường hợp khó nhất: một yêu cầu ghi phải qua vòng phê duyệt (MRTR) trước khi chạm vào nguồn dữ liệu.

1

Bước 4-5 trả lời "ai được ghi". Policy engine kiểm tra scope và tenant trước khi server chạy tool. Từ chối thì trả 403 / -32021 và dừng tại đây, không xuống các bước sau. readOnlyHint của server không được dùng làm phân quyền.

2

Bước 6-11 là chỗ đặt phê duyệt. Server trả input_required thay vì ghi ngay. Người dùng xác nhận ở bước 7-8, client gọi lại với id mới ở bước 9. Bước 10-11 xác thực requestState (ký hoặc AEAD, gắn user · tenant · tool · hash tham số gốc · hạn dùng · nonce một lần) và đối chiếu idempotency_key để không ghi trùng.

3

Credential và trace không nằm trên wire. Credential do host/control plane giữ, không bao giờ xuống model. Trace · audit được ghi xuyên suốt mọi bước trong control plane. Với yêu cầu chỉ đọc, bỏ bước 6-9: server trả thẳng complete.

Control plane là gì và nằm ở đâu

Control plane không phải một server bắt buộc. Nó là một lớp trách nhiệm, không phải một tiến trình. MCP server vẫn gọi API nghiệp vụ như bình thường - đó là data plane. Control plane là phần code quyết định và ghi nhận bao quanh lời gọi đó, không thay thế nó.

Trong lab, control plane chỉ là middleware

# Cùng một process MCP server. Không có server thứ hai.
# ---- CONTROL PLANE: quyết định, trước khi chạm nghiệp vụ ----
policy = cp.evaluate(user, tenant, tool="update_task_status", args)
if policy.deny:               raise ToolError(403)
if policy.needs_approval and not request_state:
                              return InputRequired("Cập nhật T-1042 sang done?")
if request_state:             cp.verify_state(request_state, hash(args))
if cp.seen(idempotency_key):  return cp.cached_result(idempotency_key)

# ---- DATA PLANE: gọi API nghiệp vụ thật ----
result = tasks_api.patch(f"/tasks/{task_id}", json={"status": status})

# ---- CONTROL PLANE: ghi nhận ----
cp.record(idempotency_key, result)   # idempotency + trace
return result

Vì sao không nhét vào API nghiệp vụ? API nghiệp vụ dùng chung cho web, mobile và dịch vụ khác; nó không nên biết "agent MCP đã được duyệt chưa". Nhét logic agent vào đó là phải sửa mọi API cho mọi agent.

!

Vì sao không để model tự quyết? Model là dữ liệu không tin cậy, bị prompt injection điều khiển được. "Được ghi hay không" phải được thực thi ngoài model, ở control plane.
